# MKB-063 — MCP-сервер: внесение расходов ИИ-агентом

Цель: альтернативный способ добавлять операции. Пользователь даёт ИИ-агенту (Claude, ChatGPT,
DeepSeek через MCP-клиент) банковскую выписку или скрин; агент сам вносит расходы/доходы в бот и
передаёт остаток на счёте для сверки.

## Принятые решения (по ответам владельца)

| Вопрос | Решение |
| --- | --- |
| Авторизация | Секретная ссылка `https://<домен>/mcp/<токен>`. Токен создаётся во вкладке, хранится хэшем (sha256), показывается один раз, отзывается кнопкой. |
| Остаток на счёте | Сверка: агент присылает снимок (счёт, сумма, валюта), бот сохраняет его и показывает расхождение с расчётным балансом. Ничего не правится автоматически. |
| Вкладка | Свёрнутая карточка «Подключить ИИ» в Профиле, нижняя панель не меняется. |
| Защита | Ключ идемпотентности `external_id`, лимиты токена, пометка `source = mcp`, журнал и удаление. |

## Совместимость с клиентами

- Транспорт: MCP Streamable HTTP (stateless, JSON-ответы) на том же Nest-сервере, за тем же Caddy.
- **Claude** (claude.ai, Desktop, Code) и **ChatGPT** (режим разработчика) подключают удалённый сервер
  по URL. Их веб-интерфейсы принимают только OAuth или «без авторизации», поэтому токен лежит в URL.
- **DeepSeek** сам MCP не реализует: инструменты вызывает клиент (Cherry Studio, LibreChat и т. п.),
  а модель получает их как function calling. Для него подходит та же ссылка.
- Инструменты возвращают обычный текст с JSON — этого достаточно любому клиенту.

## Инструменты MCP

| Инструмент | Назначение |
| --- | --- |
| `list_categories` | категории пользователя (агент обязан брать названия отсюда) |
| `add_transactions` | пакет до 50 операций: `type`, `amount`, `currency`, `category?`, `note?`, `date?`, `external_id?`; ответ по каждой: `created` / `duplicate` / `error` |
| `report_balance` | снимок остатка (`account`, `amount`, `currency`, `as_of?`) + расхождение с расчётным балансом |
| `get_recent` | последние операции (с `id` и `source`) |
| `delete_transaction` | отмена записи, сделанной через MCP (чужие и ручные записи недоступны) |

## Этапы

1. **Данные.** Миграция `sql/014_mcp.sql` (идемпотентная): `transactions.source`, `transactions.external_id`
   + уникальный индекс `(user_id, external_id)`, таблицы `mcp_tokens` и `account_balances`.
   Новые таблицы добавляются в `eraseUserData`.
2. **Чистая логика без БД** (`src/mcp/tokens.ts`, `src/mcp/rules.ts`): генерация и хэш токена,
   проверка операции, время операции из `date` в часовом поясе пользователя, лимитер, сверка остатка.
3. **MCP-сервер** (`src/mcp/server.ts`): инструменты через внедряемые зависимости `McpDeps`,
   поэтому тестируются без БД. DB-реализация — `src/mcp/deps.ts`, `src/db/mcp.ts`.
4. **HTTP-вход** (`src/nest/mcp.controller.ts`): `POST /mcp/:token` → токен → пользователь → лимит →
   транспорт. `GET`/`DELETE` → 405. Управление токенами для вкладки — `src/nest/api/mcp.controller.ts`
   (под `TelegramAuthGuard`).
5. **Вкладка** (`webapp/src/features/connect-ai`): создать ссылку, скопировать, список и отзыв,
   инструкции для Claude / ChatGPT / DeepSeek, журнал записей от ИИ с удалением, снимки остатка и расхождение.
6. **Документация и выкатка.** `DEPLOY.md`: не логировать `/mcp/*` в Caddy. Деплой — только по запросу.

## Тесты

Автоматические (`npm test`, без БД):
- токены: формат, хэш стабилен, два токена различаются;
- правила: сумма/валюта/тип/категория/дата, будущая дата отклоняется, лимитер (окно, сброс), сверка остатка;
- **протокол MCP целиком**: настоящие `Client` ↔ `McpServer` через `InMemoryTransport`:
  `tools/list`, `add_transactions` (создание, дубль по `external_id`, ошибка в одной из операций не
  валит остальные), `report_balance`, `delete_transaction` только для `source = mcp`;
- **HTTP-уровень**: тот же сервер на `http.createServer` + `StreamableHTTPClientTransport`.

Вручную (по `docs/RELEASE_CHECKLIST.md`): подключить ссылку в Claude, затем в ChatGPT, затем в Cherry Studio
с DeepSeek; отправить выписку из 5 строк, повторить отправку (дублей быть не должно), отозвать токен
(следующий вызов — 401), удалить запись из вкладки.

## Риски

- Ссылка = пароль: Caddy не должен писать `/mcp/*` в access-лог, токен не попадает в логи бота.
- Рассчитанный баланс считается по всем записанным операциям, поэтому при первой сверке расхождение
  равно «начальному остатку» — это нормально и объясняется в интерфейсе.
- Категории: неизвестная категория отклоняется с подсказкой вызвать `list_categories`, чтобы не засорять статистику.
