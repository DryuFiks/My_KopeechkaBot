# 💰 My Kopeechka Bot

**Personal finance Telegram bot** для учёта доходов и расходов, конвертации валют и (в перспективе) регулярных платежей и аналитики.

Проект разрабатывается на **Node.js, TypeScript, grammY и PostgreSQL**. Основная цель — вести личный бюджет прямо в чате, без отдельных приложений и таблиц.

> ✅ **MVP (Sprint 1) и версия 0.0.1 (Sprint 2) реализованы.** Ниже — актуальное описание того, что уже работает, и того, что запланировано дальше (Sprint 3 / 0.0.2).
> Подробный технический план по спринтам — `finance_bot_plan_detailed.txt` в корне репозитория.

## ✨ Возможности

### 📊 Учёт доходов и расходов

* ✅ Запись операции одной текстовой строкой (без пошаговых меню): `-150 rub еда обед`, `+2000 gel фриланс`.
* ✅ Знак определяет направление: `-` расход, `+` доход.
* ✅ Просмотр последних 10 операций (`/last`).
* ✅ Отмена последней операции текущего пользователя (`/undo`), устойчиво к гонке двух почти одновременных запросов.
* ✅ Сводка доходов, расходов и баланса за день (`/today`) и за месяц (`/month`).

### 🗂️ Категории операций

* ✅ Категория — первое слово после суммы и валюты, всё остальное — заметка.
* ⏳ Стандартный/расширяемый список категорий, аналитика по категориям — в 0.0.2 (`/stats`).

### 💱 Конвертация валют

* ✅ Поддерживаемые валюты: **RUB, GEL, USD**; по умолчанию — **GEL**.
* ✅ Курсы — со страниц Google Finance (RUB→GEL и USD→GEL), с кэшем на 24 часа. Парсинг HTML не является официальным API Google и может перестать работать при изменении страницы.
* ✅ Если API недоступен — используется последний сохранённый курс (кэш переживает перезапуск бота, хранится в БД); если курса ещё нет вообще — операция сохраняется с пометкой "курс недоступен", а не с фиктивным значением.
* ✅ `/rate` показывает текущие курсы, время последнего обновления и явно помечает устаревшие (fallback) курсы.

### 🔁 Регулярные платежи

* ⏳ Запланировано на 0.0.2 (см. R1–R3 в `finance_bot_plan_detailed.txt`): таблица `recurring`, команды `/recurring add|list|remove|toggle`, планировщик списаний и уведомления.

### 📈 Финансовая аналитика

* ✅ Сводка за день и за месяц с балансом и числом операций.
* ⏳ Статистика по категориям (`/stats`) и экспорт в CSV (`/export`) — 0.0.2 (R4–R5).

### 🔐 Пользовательские данные

* ✅ Все операции читаются/изменяются/удаляются строго по Telegram `user_id`.
* ✅ Хранение в PostgreSQL, все запросы параметризованы (без конкатенации пользовательского текста в SQL).
* ✅ Конфигурация через переменные окружения (`.env`, не коммитится).

## 🗄️ Структура базы данных

Актуальная схема (см. `sql/schema.sql` и `sql/002_add_rate_cache.sql`):

### `transactions`

| Поле         | Тип                  | Описание                                                |
| ------------ | --------------------- | ---------------------------------------------------------- |
| `id`         | SERIAL PRIMARY KEY    | Идентификатор операции                                     |
| `user_id`    | BIGINT NOT NULL       | Telegram user_id владельца                                  |
| `type`       | VARCHAR(10)           | `'expense'` или `'income'`                                  |
| `amount`     | NUMERIC(12,2)         | Сумма (положительная), знак направления — в поле `type`      |
| `currency`   | VARCHAR(3)            | `RUB`, `GEL` или `USD`                                      |
| `amount_gel` | NUMERIC(12,2), NULL   | Сумма в GEL на момент записи; `NULL`, если курс был недоступен |
| `category`   | VARCHAR(50), NULL     | Первое слово после суммы/валюты                              |
| `note`       | VARCHAR(200), NULL    | Остаток текста                                               |
| `created_at` | TIMESTAMPTZ           | Время создания (по умолчанию `NOW()`)                        |

Индексы: `user_id`, `created_at`, составной `(user_id, created_at DESC)`.

### `rate_cache`

| Поле          | Тип           | Описание                                    |
| ------------- | ------------- | -------------------------------------------- |
| `currency`    | VARCHAR(3) PK | Валюта (кроме GEL, у которой курс всегда 1)   |
| `rate_to_gel` | NUMERIC(14,6) | Последний известный курс к GEL                |
| `fetched_at`  | TIMESTAMPTZ   | Когда курс был получен от Google Finance                 |

Таблицы `users`, `categories`, `recurring_payments`, упомянутые в ранней (проектной) версии README, будут введены в 0.0.2 вместе с `/recurring` и `/stats` (см. R1 в техническом плане); отдельная таблица `users` пока не нужна — все данные и так изолированы по `user_id`.

## ⚙️ Установка и запуск

### Требования

* Node.js ≥ 18 (используется глобальный `fetch` для запроса курсов).
* npm.
* PostgreSQL — в этом проекте используется контейнер Docker.
* Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

### 1. Клонирование репозитория

```bash
git clone https://github.com/DryuFiks/My_KopeechkaBot.git
cd My_KopeechkaBot
```

### 2. Установка зависимостей

```bash
npm install
```

**Windows / PowerShell:** если получаешь ошибку `выполнение сценариев отключено в этой системе`, разово разреши локальные скрипты для своего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

либо используй `npm.cmd install` / `npm.cmd run dev`.

### 3. База данных в Docker-контейнере

Создай базу и накати схему (замени `<container_id>` и `-U postgres` на свои, если отличаются):

```bash
docker exec -it <container_id> psql -U postgres -c "CREATE DATABASE finance_bot;"
```

```powershell
# PowerShell — начальная схема
Get-Content sql/schema.sql | docker exec -i <container_id> psql -U postgres -d finance_bot
# затем миграция 0.0.1 — таблица кэша курсов
Get-Content sql/002_add_rate_cache.sql | docker exec -i <container_id> psql -U postgres -d finance_bot
```

(В bash/Linux вместо `Get-Content файл |` используй `psql ... < файл`.)

Проверка:

```bash
docker exec -it <container_id> psql -U postgres -d finance_bot -c "\dt"
```

Должны быть видны `transactions` и `rate_cache`.

### 4. Настройка окружения

```bash
cp .env.example .env
```

```env
BOT_TOKEN=токен_от_BotFather_без_кавычек
DATABASE_URL=postgres://postgres:postgres@localhost:5432/finance_bot
```

Узнать проброшенный порт контейнера: `docker port <container_id>`.

### 5. Запуск в режиме разработки

```bash
npm run dev
```

При старте бот: проверяет подключение к БД → загружает кэш курсов из `rate_cache` → при необходимости запрашивает свежие курсы у Google Finance → начинает polling. Ошибки на каждом из этих шагов пишутся в консоль и в `logs/`.

### 6. Продакшн-сборка

```bash
npm run build
npm start
```

Автозапуск/перезапуск процесса (pm2 или аналог) — операционная задача Sprint 2 (V7), настраивается на твоей машине под конкретную ОС.

## 🤖 Команды бота

Операции добавляются **не через отдельную команду**, а обычным текстовым сообщением (см. примеры ниже) — это осознанный выбор в пользу скорости ввода одной строкой без диалогов.

| Команда   | Описание                                                    |
| --------- | ---------------------------------------------------------------- |
| `/start`  | Приветствие и краткая справка                                     |
| `/help`   | Полный формат ввода и список команд                               |
| `/today`  | Доходы, расходы и баланс за сегодня                               |
| `/month`  | Доходы, расходы и баланс за текущий месяц                         |
| `/last`   | Последние 10 операций                                             |
| `/undo`   | Отменить последнюю операцию (только свою)                         |
| `/rate`   | Текущие курсы валют, источник и время последнего обновления       |

Команды `/stats`, `/export`, `/recurring` появятся в 0.0.2.

## 💬 Примеры использования

**Запись операций**

```text
Пользователь: -150 rub еда обед
Бот: Расход записан: 150.00 RUB, категория: еда (≈ 4.50 GEL)

Пользователь: +2000 gel фриланс
Бот: Доход записан: 2000.00 GEL, категория: фриланс (≈ 2000.00 GEL)

Пользователь: -12.50 usd подписка
Бот: Расход записан: 12.50 USD, категория: подписка (≈ 33.75 GEL)
```

**Сводка за день/месяц**

```text
Пользователь: /today
Бот:
Итоги за сегодня
Доходы: +2000.00 GEL
Расходы: -38.25 GEL
Баланс: 1961.75 GEL
Операций: 3
```

**Курсы валют**

```text
Пользователь: /rate
Бот:
Текущие курсы (источник: Google Finance):
GEL → 1 GEL
RUB → 0.03 GEL (обновлено 2026-09-27 08:00)
USD → 2.7 GEL (обновлено 2026-09-27 08:00)
```

## 🛡️ Обработка ошибок и логи

* Некорректный ввод (пустое сообщение, `-abc`, `-0 gel`, неизвестная валюта) отклоняется парсером и не создаёт запись — пользователю показывается понятная причина.
* Неожиданные ошибки (сбой БД, сбой сети при запросе курсов, ошибка Telegram API) перехватываются централизованно: пользователь видит нейтральное сообщение, детали — только в логах.
* Логи пишутся в `logs/bot-YYYY-MM-DD.log` (новый файл на каждый день) с уровнями `INFO`/`WARN`/`ERROR`; токены и `DATABASE_URL` из логов вычищаются автоматически.
* Сбой Telegram API при отправке ответа не приводит к падению обработчика — ошибка логируется, но не выбрасывается повторно.

## 🧪 Тестирование

Автоматические тесты пока не написаны (перенесено в бэклог). Ручная проверка — по сценариям M8 в `finance_bot_plan_detailed.txt`:

* Добавление дохода и расхода в разных валютах.
* `/today`, `/month` — сверка сумм вручную.
* `/last`, `/undo` — в том числе повторный `/undo` на пустой истории.
* Некорректный ввод: пустое сообщение, `-abc`, `-0 gel`, `-10 xyz` (несуществующая валюта).
* Перезапуск бота — данные и кэш курсов должны сохраниться.
* Временная недоступность Google Finance — `/rate` должен показать пометку об устаревшем курсе, а не упасть.

## 🧭 Принципы разработки

* **MVP first** — сначала минимальная рабочая версия.
* **Incremental development** — небольшие последовательные изменения, один спринт — один прирост функциональности.
* **Type safety** — использование возможностей TypeScript.
* **Data integrity** — параметризованные запросы, изоляция данных по `user_id`, явная пометка отсутствующего курса вместо фиктивных значений.
* **Security** — секреты только в `.env`, не в логах и не в ответах пользователю.
* **Testability** — бизнес-логика (`parser.ts`, `currency.ts`) не зависит от Telegram и БД и может быть проверена отдельно.

2. Выполни `npm install` и `npm run build`.
3. Запускай бота через `start.bat`, а не напрямую через `npm start`.
4. После обновления файлов снова выполни `npm run build`, затем нажми в Telegram `/start` или `/menu`. Кнопка «🔄 Перезапуск» завершит текущий процесс специальным кодом, и `start.bat` запустит его снова.

Кнопка перезапуска доступна только пользователю, чей ID указан в `ADMIN_TELEGRAM_ID`. Она перезапускает уже собранную версию из `dist`, поэтому после изменения исходников сначала обязательно выполни `npm run build`.
